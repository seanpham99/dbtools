Native Multi-Engine Dialects

Seamless execution across SQL Server (MSSQL with GO-batching), PostgreSQL (with clean session-state isolation), and serverless SQLite.

🔒

Zero-Drift Cryptographic Ledger

Records applied migrations with SHA-256 content hashes in dbtools_migration_history to catch silent post-apply script tampering.

🔍

Read-Only Drift Verification

dbtools verify introspects live objects against migration definitions and understands drop lifecycles so legitimate drops aren't flagged as drift.

🛡️

Target Safety & Secret Hygiene

Environments map through url_env variables in dbtools.toml. Production targets require explicit confirmation and reject destructive commands.

🐍

Python Type Contract Generation

dbtools generate renders versioned, type-safe Pydantic v2 BaseModels from live schema metadata, with --check for CI schema sync.

Command Reference

A concise set of focused, predictable CLI operations.

Command Usage Description
init dbtools init Creates starter dbtools.toml and migrations/ directory.
new dbtools new <name> Scaffolds a timestamped {ts}_{name}.up.sql migration file.
up dbtools up [--target local] Applies pending migrations to local target. Refuses protected targets.
push dbtools push <target> [--yes] Applies pending migrations to named remote target with explicit confirmation.
status dbtools status [--json] Displays applied/pending migration status across all configured targets.
verify dbtools verify <target> Read-only audit: checks file SHA hashes and database object existence. Non-zero exit on drift.
repair dbtools repair <target> <v>:<status> --yes Corrects ledger record status and resynchronizes the version cursor safely.
reset dbtools reset [--yes] Local-only: drops database, replays all migrations, and runs seed.sql.
generate dbtools generate [target] [--out models.py] Introspects schema and outputs typed Pydantic Python models.
dashboard dbtools dashboard Interactive Bubble Tea TUI monitor (r to refresh, q to quit).
