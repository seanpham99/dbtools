Multi-Engine Native Dialects

Purpose-built execution engines with zero external runtime drivers or CGO dependencies.

SQL Server
MSSQL

Enterprise-grade schema authority for Microsoft SQL Server and Azure SQL Database.

  • ✓Native T-SQL GO batch splitting and token parsing
  • ✓Distributed transactional application locking (sp_getapplock)
  • ✓Multi-schema introspection (sys.tables, sys.columns)
PostgreSQL
Postgres

High-performance transactional migrations for PostgreSQL 12 through 17+ and Supabase.

  • ✓Transactional DDL execution with automatic rollback
  • ✓Session-state isolation via connection reset
  • ✓Advisory locking to prevent concurrent migration collisions
SQLite
Zero-Config

Blazing fast, pure-Go file-based database for local dev-loops, integration testing, and edge nodes.

  • ✓Pure Go (modernc.org/sqlite) — Zero CGO requirements
  • ✓Foreign key enforcement & schema introspection via PRAGMA
  • ✓Ideal for ephemeral Docker containers and CI pipelines

Engineered for Technical Authority

Solving the subtle, silent failure modes of legacy scalar-cursor migration runners.

🔒

Zero-Drift Cryptographic Ledger

Tracks applied migrations with SHA-256 content hashes in dbtools_migration_history alongside traditional cursors to instantly catch post-execution script tampering.

🔍

Drop-Aware Drift Verification

dbtools verify introspects live objects against migration definitions and tracks drop lifecycles, ensuring legitimate drops are excused without false alerts.

🛡️

Target Protection & Secret Hygiene

Database targets are referenced via url_env environment variables in dbtools.toml. Production targets reject destructive operations without explicit --preview --yes.

↩️

Soft Revert vs Hard Down

dbtools rollback performs a non-destructive ledger soft-revert (the safe prod verb), while dbtools down safely executes .down.sql reverse DDL.

🤖

Agent-First Ergonomics

Designed for CI and AI agents: predictable Terraform-style exit codes (0 clean / 1 error / 2 drift), universal --json, and DBTOOLS_NO_PROMPT=1 fail-closed mode.

Built for Autonomous Agents & CI Pipelines

AI coding assistants (Claude Code, Cursor, Hermes, Copilot) and automated release pipelines need predictable, deterministic behavior. dbtools never hangs waiting for stdin when piped or running in agent environments.

Exit-Code Contract

0: Clean / Up-to-date
1: Operational error
2: Pending changes or ledger drift

Universal --json

Every query command (status, plan, verify, doctor) outputs clean structured JSON on stdout for immediate programmatic consumption.

DBTOOLS_NO_PROMPT=1

Automatically active in non-TTY environments. Destructive operations fail closed instead of blocking background tasks.

CLI Command Reference

A concise, predictable vocabulary for development and release workflows.

Command Usage Description
init dbtools init Creates starter dbtools.toml configuration and migrations/ directory.
new dbtools new <name> Scaffolds a timestamped {ts}_{name}.up.sql migration file.
up dbtools up [--target local] Applies pending migrations to local target. Refuses protected/remote targets.
push dbtools push <target> [--yes] Applies pending migrations to named remote target with explicit confirmation.
status dbtools status [target] [--json] Displays applied and pending migration status across configured targets.
doctor dbtools doctor [target] [--json] Strictly read-only health, integrity, drift, and security audit.
plan dbtools plan [--target X] [--json] Read-only preview of pending migrations + ledger drift without applying SQL.
verify dbtools verify <target> [--json] Cryptographic audit: validates migration file SHA hashes and database objects.
down dbtools down <target> [N] [--preview] [--yes] Applies .down.sql migrations in reverse order.
rollback dbtools rollback <target> [--yes] Ledger-only soft-revert (never destroys data) — the safe production verb.
repair dbtools repair <target> <v>:<status> --yes Corrects ledger record status and resynchronizes the version cursor safely.
force dbtools force <version> [--target X] [--yes] Sets tracking version cursor and clears dirty state without executing SQL.
reset dbtools reset [target] [--yes] Unprotected targets: drops database, replays all migrations, and runs seed.sql.
generate dbtools generate [target] [--lang python|ts] [--zod] [--out file] Introspects schema and outputs typed Pydantic Python models or TypeScript interfaces (+ zod).
lint dbtools lint [--dir <path>] [--json] Statically validates filename formatting, duplicate versions, and file hygiene.
dashboard dbtools dashboard Interactive Bubble Tea TUI monitor (r to refresh, q to quit).
start / stop dbtools start [--timeout 30s] [--no-wait] / stop Starts or stops ephemeral tool-owned local database container with readiness polling.
